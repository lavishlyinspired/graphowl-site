03

Or call it from code

Your passcode is also an API key during your slot: send it as a bearer token.

export PASSCODE=OWL-XXXX-XXXX
curl -X POST https://demo.graphowl.app/sparql \
  -H "Authorization: Bearer $PASSCODE" \
  -H "Content-Type: application/json" \
  -d '{"query": "SELECT ?class (COUNT(?s) AS ?n)
        WHERE { GRAPH ?g { ?s a ?class } }
        GROUP BY ?class ORDER BY DESC(?n)"}'
from graphowl import GraphOWL

owl = GraphOWL(url="https://demo.graphowl.app",
               api_key="OWL-XXXX-XXXX", workspace="dairy-coop")
rows = owl.query.sparql("""
  SELECT ?class (COUNT(?s) AS ?n)
  WHERE { GRAPH ?g { ?s a ?class } }
  GROUP BY ?class ORDER BY DESC(?n)""")
const res = await fetch("https://demo.graphowl.app/sparql", {
  method: "POST",
  headers: { Authorization: "Bearer OWL-XXXX-XXXX",
             "Content-Type": "application/json" },
  body: JSON.stringify({ query: `SELECT ?class (COUNT(?s) AS ?n)
    WHERE { GRAPH ?g { ?s a ?class } }
    GROUP BY ?class ORDER BY DESC(?n)` }),
});
const { rows } = await res.json();

One model, four jobs

A semantic model is only useful if it does work. GraphOWL uses the same approved model to reach data, justify answers, govern change and constrain agents.

Access

Ask in business concepts

A semantic model maps Farm, MilkLot and QualityMeasurement to real tables, columns and keys. A virtual graph answers a question from the source database itself, so the data does not have to move.

Trust

Know why an answer is what it is

Every fact keeps its source and its history. Reasoning is stored apart and marked as derived, with the rule that produced it, so a conclusion can be checked or challenged.

Change

Evolve the model safely

Proposals, a review queue and decisions with reasons. Model diffs and competency questions show what a change touches before it takes effect.

Agents

Keep agents inside the rules

An MCP server with 101 tools, workspace-scoped sessions and grants. Refusals are recorded. Agents propose; people decide.

What people use it for

One engine, many domains. A data catalog, a compliance model or a product domain is one pack on the same engine.

Access

Query data where it lives

Ask a source database in place through an approved mapping, in business concepts, without bulk-copying it into a graph store.

Models

From vocabulary to executable semantics

Take terms from candidate to class, property and source mapping, with validation and a query at the end of the path.

Rules

Compliance rules

Say which records break which rule, and why, with the evidence one click away.

Agents

Guardrails for AI agents

Agents work through the model: scoped to a workspace, limited by a grant, proposing changes that a person approves.

Integration

One meaning, many systems

Reconcile inconsistent terms across databases and applications while keeping what each source means.

Catalog

Data catalog and lineage

Definitions, owners and lineage queried like any other fact, in the same graph as the domain model.

What is in the engine

The pieces the four jobs rest on.

Every fact keeps its history

Nothing is deleted, only retracted. Ask any question as it stood at an earlier moment.

Reasoning you can tell apart

OWL 2 RL derives what follows from the model, and marks it as derived so it is never mistaken for stated.

Review before effect

Models proposed by software are proposals until a person approves them. Nothing changes the graph unreviewed.

SPARQL and openCypher

Two ways to ask the same graph. SPARQL 1.1 and a documented openCypher subset, with honest errors.

Validation built in

SHACL-style constraints and quality expectations report what does not fit, without changing it.

Packs for any domain

Ontology, glossary, rules and expectations bundled per domain, so one engine serves many.

Virtual graphs

Query a source database in place, through a mapping a reviewer approved.

People and agents, one engine

A console, an HTTP API, client libraries and an MCP server, all on the same facts.

How it behaves

Three properties that follow from how the engine is built, and that you can check.

Context an AI assistant can trust

GraphOWL includes an MCP server with 101 tools. An assistant can look things up, follow relationships, run queries, propose changes and record what it learned. Every answer traces to facts and rules; agents propose and people decide.

Where it is going

GraphOWL is early access. These are the capabilities we are building toward, in no particular order. They are not all in the demo today; known limits says what is.

Plan across sources

An ontology-aware planner that chooses where each part of a question runs, pushes work down to the databases, and keeps data transfer small.

Know what a change will break

Before a class, property or mapping changes, list the queries, constraints, virtual graphs and derived facts it affects.

Trace every answer

From the business question, through ontology terms and approved mappings, to the generated source query and the rows that support the result.

Test the model

Business questions as executable regression tests, run on every proposed change, with a quality scorecard for each pack.

Governed writes

Change a business fact through the model and propagate it to the right source with authorization, validation and an audit trail.

Version the whole model

Ontology, mappings, rules and vocabulary versioned together, reviewed as semantic diffs, and reversible.

Built in Rust

The server is written in Rust, as a workspace of small, single-purpose crates.

Safe and steady

Memory safety without a garbage collector: whole classes of crashes and security flaws cannot be written in safe code, and there are no collector pauses to show up as latency spikes.

One server to run

The server, the API and the console ship as one program. No runtime or virtual machine to install, and few moving parts to operate.

Rules in the types

A fact has a source, a derived fact is marked derived, a model change needs review. These are encoded in types, so breaking them is a compile error.

What is open, and what is not

Public

  • Documentation and the full API description
  • Client libraries (Python and TypeScript, Apache-2.0)
  • Runnable examples and sample data
  • Standards conformance, dated
  • Software bill of materials and licences
  • Issues, discussions and a security policy

Not public

  • The server's source code: it is proprietary
  • Production use is not covered by the evaluation licence

GraphOWL is in early access: the API may change before 1.0, and known limits are listed plainly.
